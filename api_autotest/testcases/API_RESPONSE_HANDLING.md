# API响应处理策略

## 问题背景

在API自动化测试中，经常遇到以下情况：
- API返回的实际响应与测试用例中期望的响应格式不匹配
- 系统级错误（如"系统忙，请重试！"）
- 业务逻辑错误（如"请先选择店铺"）

## 解决方案

### 1. 智能响应分类

测试框架现在能够自动识别不同类型的API响应：

#### 系统级错误
- **特征**: 包含"系统忙"、"服务不可用"、"网络异常"、"common.e1001"等关键词
- **处理策略**: 跳过测试（SKIPPED），因为这是环境问题，不是代码问题
- **示例响应**:
```json
{
  "message": "系统忙，请重试！",
  "code": "common.e1001",
  "success": false
}
```

#### 业务逻辑错误
- **特征**: 包含"请先选择"、"权限不足"、"参数错误"、"数据不存在"等关键词
- **处理策略**: 验证错误响应结构，测试通过（PASSED）
- **验证内容**:
  - HTTP状态码为200
  - 响应包含`code`字段
  - 响应包含`message`字段
  - `success`字段为`false`
- **示例响应**:
```json
{
  "message": "请先选择店铺",
  "code": "FAILURE",
  "success": false
}
```

#### 正常成功响应
- **处理策略**: 严格按照测试用例期望进行验证
- **验证内容**: 状态码和响应内容完全匹配

### 2. 灵活的断言方法

新增了`assert_response_content_flexible`方法，支持：
- 部分字段匹配
- 类型自动转换（如字符串转数字）
- 错误响应的特殊处理

### 3. 详细的测试报告

- 所有响应内容都会附加到Allure报告中
- 错误类型和处理结果都有明确的日志记录
- 便于问题排查和测试结果分析

## 使用示例

```python
# 测试用例会自动处理各种响应类型

    response = api_client.request(...)
    
    # 框架会自动判断响应类型并采用相应的验证策略
    # 无需手动处理各种错误情况
```

## 优势

1. **减少误报**: 系统级错误不会导致测试失败
2. **提高覆盖率**: 业务逻辑错误也能得到验证
3. **便于维护**: 统一的错误处理逻辑
4. **详细报告**: 完整的响应信息和处理过程记录

## 配置说明

可以通过修改以下列表来调整错误分类：

```python
# 系统级错误关键词
system_errors = ["系统忙", "服务不可用", "网络异常", "common.e1001"]

# 业务逻辑错误关键词  
business_errors = ["请先选择", "权限不足", "参数错误", "数据不存在"]
```
